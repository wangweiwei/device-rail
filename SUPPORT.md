# Support

DeviceRail is an alpha open-source project. Community support is best effort;
there is no guaranteed response time or production support agreement.

## Where to ask

- Use a GitHub issue for a reproducible defect or a concrete feature request.
- Use a GitHub discussion, when enabled, for setup questions, design ideas, or
  platform experience that is not yet a defect report.
- Use private vulnerability reporting for security issues; never disclose them
  publicly. See [SECURITY.md](SECURITY.md).

Before asking, check the [documentation index](docs/README.md),
[platform support](docs/platform-support.md), component README, and existing
issues.

## Include in a support request

- DeviceRail version or commit;
- host OS, architecture, Rust/Node/Python versions;
- target platform and external tool versions;
- exact command and sanitized configuration names;
- expected result, actual result, and minimal reproduction;
- relevant logs with secrets and identifiers removed;
- whether the path uses fixtures, fake tools, a stock daemon, or real hardware.

Do not post access tokens, passwords, HMAC credentials, signing keys, private
endpoints, Apple or Google account information, device UDIDs/serials, or
personal screenshots.

## Scope

Maintainers can help with DeviceRail protocol, runtime, Drivers, clients,
recording, visualizers, and release tooling. Support for Apple Developer
accounts, Android Platform Tools, DevEco Studio, desktop permissions,
Playwright servers, RDP infrastructure, SSH/mTLS, CI secrets, and signing
certificates belongs to their respective vendors or deployment owners.
